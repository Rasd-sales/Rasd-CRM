هيكلية عزل بيانات الشركات وحسابات الدخول (Multi-Tenancy)

كيف نضمن بالدليل العملي أن كل مستخدم يسجل بإيميله وباسورده ولا يرى إلا بيانات شركته فقط.

اختبار عزل البيانات الفعلي في هذه الجلسة

أنت الآن مسجل الدخول باسم: م/ أحمد محمود تابع لشركة: مصنع الأهرام. كل عميل أو صفقة تضيفها الآن ستأخذ آلياً المعرف ahram. إذا قمت بالتبديل إلى حساب "شركة الدلتا" أو أنشأت شركة جديدة، ستختفي بيانات الأهرام تماماً وتظهر صفقات الشركة الأخرى فقط.

1

التسجيل وتعيين الشركة (Tenant Assignment)

عندما تسجل شركة جديدة، يتم إنشاء company_id فريد لها. وعندما يقوم صاحب الشركة بإنشاء حسابات لمناديب المبيعات، يتم ربط إيميلاتهم بنفس الـ ID تلقائياً.

2

عزل أمان مستوى الصف (Supabase RLS)

في قاعدة بيانات PostgreSQL السحابية، نقوم بوضع شرط وحيد: لا يتم جلب أي سطر بيانات إلا إذا تطابق كود الشركة مع كود الشركة الموجود في التوكن المشفر للمستخدم (auth.jwt()).

3

مستويات الصلاحيات (Roles)

المدير (Admin): يرى كل صفقات مصنعه وإجمالي المبيعات.
مندوب المبيعات (Sales Rep): يرى فقط العملاء المخصصين له داخل نفس المصنع.

كود إنشاء العزل في Supabase (SQL Script جاهز للنسخ) Row Level Security 
-- 1. تفعيل العزل على جدول الصفقات
ALTER TABLE deals ENABLE ROW LEVEL SECURITY;

-- 2. قاعدة أمان تمنع أي شركة من رؤية صفقات غيرها
CREATE POLICY "Strict Tenant Data Isolation" 
ON public.deals
FOR ALL 
USING (tenant_id = (auth.jwt() -> 'app_metadata' ->> 'tenant_id'));
